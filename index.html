What is implemented

A calmer study loop, with explicit limits.

These are product capabilities in the current codebase—not claims of better learning outcomes.

01

Budget-aware planning

Choose a daily study duration. The planner prioritizes due work and estimates whether new prompts fit today and across a seven-day forecast.

02

Flexible review

Practice a mixed session, focus on one collection, or work through urgent reviews. Supported prompts include basic, reverse, cloze, typed answer, image occlusion, and audio.

03

Device-first storage

The desktop workspace is stored locally. Backup export and restore are available, but pre-1.0 users should keep independent backups.

04

Reviewed migration

Anki package imports use a preflight step and report supported, transformed, and unsupported content before commit. Compatibility is intentionally bounded.

Read the compatibility contract →
05

Extension boundaries

Built-in modules are trusted application code. Installable SDK 2 packages use signed archives, capability review, isolated workers, and sandboxed UI.

How extension trust works →
06

Desktop releases

Published builds are available for macOS, Windows x64, and Linux x64. Updates are manual and each artifact should be verified before installation.

Before you install

A preview, not a promise.

No replacement claim. Neo Anki does not yet claim complete Anki compatibility, production maturity, or superior learning outcomes.

Desktop is the published surface. Browser and mobile clients exist in the source tree, but hosted service and real-device release gates remain.

Manual updates. The app does not download or install its own updates. Use the official GitHub Releases page.

Features can be unreleased. The main branch may describe work that is newer than the latest published binary; release notes are the authority for shipped behavior.

Open development

Inspect the work, then decide.

The source, tests, architecture notes, compatibility limits, and security policy are public.
