What catalog review checks

01

Submission

A publisher proposes one catalog entry through a pull request in the public marketplace repository.

02

Automated validation

Checks cover schema, package URL, size, SHA-256, signed manifest metadata, SDK version, permissions, repository identity, and signing-key continuity.

03

Maintainer review

Review covers publisher control, source and build provenance, permissions, privacy and network behavior, licensing, UX, and pedagogical claims.

04

User confirmation

Desktop revalidates the approved release, then shows the package’s requested capabilities before the user confirms installation.

Runtime and trust boundary

Neo Anki application

Stable study foundation

Neo Anki provides storage, scheduling, review, validation, and the controls that extensions use.

Installable extensions

Independent and permission-based

Each extension has its own repository and release. Neo Anki shows its requested permissions before installation and limits it to those permissions while running.

Important: a signature proves that a package matches its signed bytes; it does not prove the publisher’s real-world identity or that the code is safe. Isolation reduces access but does not remove all risk. Review the publisher, source, network domains, and requested capabilities.

Availability

  • The current main branch contains marketplace discovery for desktop, browser, and mobile clients.
  • Only the desktop client has an installable extension runtime; browser and mobile discovery is browse-only.
  • Neo Anki v0.3.0 and later include marketplace discovery and extension installation. In Settings → Extensions, select Review & install, confirm the requested permissions, and reload when prompted.
  • Extension updates are reviewed and installed explicitly; there is no silent automatic update path.
