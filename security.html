Security

Report suspected vulnerabilities privately. Do not publish an exploit, private learning data, credentials, or unredacted diagnostics in a GitHub issue.

Supported versions

Neo Anki is pre-1.0. Security fixes are applied to the latest published release and the main branch; older releases may not receive fixes. See the repository’s normative security policy for current scope.

In scope

  • Electron main process, preload bridge, and renderer boundary
  • Workspace persistence, backups, migrations, importers, and retained source packages
  • Sync protocol, clients, service, credentials, and encryption boundaries
  • Release distribution, checksums, SBOMs, signatures, and provenance attestations
  • Extension package validation, marketplace client, runtime isolation, lifecycle, and SDK capabilities

Release trust

Install only artifacts published by neoanki/neo-anki. Verify both the release checksum and GitHub build-provenance attestation. The current v0.2.2 macOS and Windows packages are unsigned; platform signing and notarization are optional future improvements, not CI or release blockers. See download and verification guidance.

Public bugs

Non-sensitive defects can be reported in the public issue tracker. Remove learning content, local paths, account details, tokens, and other private information from screenshots and logs.
